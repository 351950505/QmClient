- SDL3 使用官方 3.4.18 源码，固定下载地址和 SHA-256；各平台和 Android Java 使用同一份源码。
- 保持已有配置键位编号、窗口模式、IME 候选栏行为、声音和语音功能。使用显式映射处理 SDL3 变动的扫描码。
- 重审 SDL3 的返回值、对象所有权、主线程约束及音频流生命周期，不能只替换 API 名称。
- Android 录音权限按异步结果处理，不能把请求成功当作授权成功。
- 语音保持现有 Opus 编码和 RV01 数据包。只有实际协议或服务依赖变化才部署中转服务器。
- Gemini 已进行只读方案讨论；其建议按官方头文件和真实调用路径核实后采纳。

## 迁移实现与复核记录

- SDL3 静态库与项目使用相同 Windows CRT；显式链接系统 `uuid` 库，避免与仓库的同名工具目标冲突。
- 输入保留原键位编号；SDL3 新增且没有旧绑定含义的扫描码返回未知键，避免误触发旧鼠标或手柄绑定。
- Windows IME 钩子将原生通知排入 SDL 事件队列；关闭输入时清除专属事件及保存的通知，避免重新打开后由旧标记提前消费新通知。
- 游戏声音和语音使用 SDL3 转换流，按应用格式分块供给完整帧；音频测试直接使用真实 SDL 转换流，不依赖声卡。
- 音频子系统由主线程取得独立引用，热插拔回调仅设置原子标记；销毁流后再释放缓冲区和引用。
- Android 权限回调只保存进程期原子状态，组件关闭后不会访问已经销毁的对象。本地服务器在权限结果返回后启动，取消时清除待办参数，连接和教程超时等待权限结束。
- SDL 窗口查询在主线程完成，窗口指针和实际 drawable 尺寸传给渲染命令；Metal 保留首帧与截图的像素尺寸语义。
- 工作流固定 SDL3 源码版本并缓存下载包；Android Java 绑定从同一 ABI 的源码目录复制，移除 SDL2 DLL、framework 和旧 IME 补丁链。
- Gemini 已参与两轮方案讨论和实现复核。实现复核中提出的晚到回调 UAF、热插拔直接重建流和空请求死锁未得到当前代码支持，不作为确定缺陷记录；实际代码与 SDL3 头文件核实继续进行。

语音服务器源码只转发 RV01/Opus 数据，不依赖 SDL。当前迁移没有改变语音数据包、帧长或服务器接口，因此暂不需要部署服务器；最终复核若发现实际兼容需求再更新服务。

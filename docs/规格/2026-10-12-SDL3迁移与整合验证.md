## SDL3 实现与兼容

- SDL3 固定为官方 3.4.18，校验下载包 SHA-256。各平台使用同一份源码，Android Java 绑定来自对应 ABI 的源码目录。静态库沿用 Windows CRT，显式链接系统 `uuid` 库，避免与仓库工具目标冲突。
- 保留现有键位配置编号，以显式映射处理 SDL3 扫描码变化。没有旧绑定含义的新扫描码返回未知键，不能误触发鼠标或手柄。整数边界接口可以检查负数和越界值，无需先构造无效 SDL 枚举。
- SDL3 长文本按完整 UTF-8 字符分成现有事件容量可接收的片段，保留空提交通知。覆盖长 ASCII、中文、四字节字符及容量边界。
- Windows IME 将原生通知按顺序排入 SDL 事件队列；关闭输入时清理专属标记和通知。非 Windows 平台采用 SDL3 候选事件。
- 窗口查询在主线程执行，将窗口和实际 drawable 尺寸交给渲染命令。保留 OpenGL、Vulkan、Metal 的初始化、首帧、截图及失败回退路径。恢复原基线合并时丢失的 Metal 后端解析、工厂、窗口标记和关闭接线，并增加 macOS 原生 Metal 启动截图 CI。
- 游戏声音和语音使用 SDL3 转换流，按应用格式供给完整 S16 帧。音频子系统由主线程取得独立引用；热插拔回调只设置原子标记，停止工作线程并销毁流后再释放缓冲区和引用。
- Android 录音权限使用异步状态，等待授权时不提前录音、启动本地服务器或连接；取消时清除待办参数。回调只访问进程期原子状态，组件关闭后不会访问旧对象。
- 移动端截图继续通过现有 `IClient::ViewFile` 打开；桌面查看器独立拥有 SDL 窗口、纹理和进程生命周期。iOS 入口与原生窗口属性改用 SDL3 接口。
- 无窗口地图工具保留 `BACKEND_NO_SDL` 边界。macOS 在顶层初始化 Objective-C / Objective-C++；Android 固定 r27d 并遵守工作流指定 NDK，替代无法编译现有 C++20 Rust 连续迭代器的 r26b。

## 审查确认并处理的问题

- 真实客户端首次启动在 `OnConsoleInit` → IME 初始化 → `StopTextInput` 查询尚未初始化的输入接口。初始化接口指针，并让窗口未就绪时返回空。
- 真实退出路径先关闭图形后端，再关闭输入，窗口 ID 查询访问已销毁后端。无后端时返回 SDL 无窗口语义的 0。
- 配置列表应用或清空暂存值时，活动输入指针可能指向即将销毁的缓存。销毁前先停用对应输入，避免帧末 IME 校验访问旧对象。
- ASan/UBSan 检出回归测试构造负扫描码枚举时的未定义行为。映射接口改用整数后仍保留负数及越界断言；无声卡的 headless CI 显式使用 SDL dummy 音频设备，保留真实转换流、回调和泄漏检测，没有增加 sanitizer 豁免。
- 资源缩略图上传预算不足时，回调可以留到下一帧，原接线却引用了上一帧的局部查找器。改为回调按值持有查找器和资源句柄，并继续通过 epoch、索引和名称拒绝过期资源。此项来自静态所有权与延迟队列路径复核，没有声称已自动复现旧栈引用。
- 严格 clang-tidy 对控制台选区可选范围提出未检查诊断。调用关系可以推出其有效，但现在显式检查后再访问，继续保留选区外的快速返回；此项没有作为已复现崩溃报告。
- 回放测试先保存并断言采样结果，再比较位置和缩放；裁剪生产接口同样显式检查采样结果。严格 optional 诊断对 GoogleTest 终止断言的识别使用 LLVM 23.1.2 复核，LLVM 22 的对应误报见 [上游问题 #181737](https://github.com/llvm/llvm-project/issues/181737)。没有关闭该检查或削弱断言。

审查沿玩家入口、所有权、状态转换及直接调用点覆盖上述 13 项任务和 SDL3 平台层，包括取消、失败恢复、重复调用、持久化兼容、线程、关闭顺序和热路径。回放摄像机仍仅影响 demo，截图与编辑器不改地图格式，语音不改数据包。Gemini 参与两轮方案讨论及音频实现只读复核；建议均通过真实源码和 SDL3 头文件核实，未把不成立的 UAF、死锁猜测列为确定缺陷。

## 工作流改进

- 缓存固定 SDL3 下载包，移除旧 SDL2 运行库、framework 和 IME 补丁链；普通、便携及 Setup 包校验禁止旧 SDL2 载荷。
- 配置使用检查先预筛候选，再执行原正则上下文判断。同一工作区从超过 8 分钟未结束降至约 7 秒完成，识别 915 个配置项，并补成员、命令与无效上下文回归。
- gate 与 benchmark 默认构建并行度统一为 6；gate 支持 `QM_GATE_BUILD_JOBS`，验证时分配资源份额。同一构建目录保持串行。
- 进程测试复用开关一致的隔离配置，每个场景仍增量构建当前源码，避免重复配置及误测旧程序。
- POSIX FIFO 改为非阻塞连接、有界重试和进程退出检查；失败保留日志，句柄转换失败时关闭描述符。macOS Metal CI 增加总超时及诊断产物。
- 进程日志规范化补齐 `T` 级别，修复地图已经加载而背景切换测试仍超时的误报，保留正常、失败恢复和立即退出场景。
- 本地 clang-tidy 只扫描当前编译数据库中的翻译单元，避免 Windows 误扫 Android 专属源文件；未参与本平台构建的文件明确列为跳过，由对应平台 CI 验证。损坏或缺失的编译数据库仍报错。
- CodeQL 保留 RelWithDebInfo 和可选功能的编译覆盖，关闭仅用于成品链接的 IPO，减少分析任务中的额外链接工作；发布构建继续使用原 IPO 配置。

## 语音中转服务

服务器源码只转发 RV01/Opus 数据，不依赖 SDL。迁移保持 48kHz 单声道 S16、20ms 帧及原 RV01 包结构和服务器接口，当前没有服务器兼容改动或部署需求。没有仅因客户端依赖更新而重启线上服务。
